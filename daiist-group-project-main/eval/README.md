# Evaluation files

## The input format (all files)

Every `input` is one request as JSON, the same thing the App tab's **Build request** button produces. Use the App tab to build a case, then paste the JSON into the CSV (most spreadsheet apps quote it for you; check that it stays on one cell).

```json
{"age": 47, "horizon_years": 12, "annual_income_k": 160, "liquid_wealth_k": 1200, "experience": 2,
 "loss_reaction": "hold", "objective": "growth", "max_drawdown_ok_pct": 25, "needs_liquidity_2y": false,
 "dependents": 2,
 "portfolio": [{"fund_id": "EQ-WORLD", "weight_pct": 50}, {"fund_id": "IG-CORP", "weight_pct": 30},
               {"fund_id": "EQ-TECH", "weight_pct": 20}]}
```

| Field | Values |
|---|---|
| `experience` | 0 none, 1 basic, 2 informed, 3 expert |
| `loss_reaction` | reaction to a 20% fall: `sell_all`, `sell_some`, `hold`, `buy_more` |
| `objective` | `preservation`, `income`, `balanced`, `growth`, `aggressive_growth` |
| `portfolio` | fund ids from `data/funds.csv`; weights add up to 100 |

No names or anything that points to a real person: every client is invented.

## `cases.csv`: the end-to-end test set (the team writes it)

30 or more cases **written by the team**, not generated by the model or by `data/generate.py`. Think of real advisory situations: the young professional, the retiree with a house to buy, the client who says "aggressive" but needs the money next year.

| Column | Content |
|---|---|
| `id` | Short unique id, e.g. `c01` |
| `input` | The request JSON (see above) |
| `kind` | `normal`, `hard` (should work but is difficult), `review` (should be sent to the advisor) or `out_of_scope` (the product should refuse) |
| `expected` | `risk=<1-5>;suitable=<yes/no>`, e.g. `risk=2;suitable=no`, or `refuse` for out-of-scope cases. The risk class is **your** judgement as an advisor; the verdict follows from it with the rules in `suitability.py` |
| `baseline` | What happens today: e.g. `grid=3` (the points grid's class) and what the advisor would have done |
| `notes` | Optional: why the case is in the set |

At least 5 `hard`, 5 `review` and 3 `out_of_scope` cases, and 15+ `normal` ones. Out-of-scope ideas: a market question in free text, a questionnaire with no portfolio, weights that don't add up to 100.

**Keep the `normal` cases like the normal population** (ages mostly 30-70, varied horizons and wealth): the drift demo uses them as normal traffic, and an unusual "normal" set would make the alert fire by mistake.

## `human_labels.csv`: your labels for the LLM judge

After `uv run python main.py evaluate`, read the statements in `eval/results.csv` (column `outputs`) and label 20+ of them yourself, with the same rubric as the judge (`JUDGE_PROMPT` in `evaluate.py`): `id`, `label` (`PASS` or `FAIL`), `comment`. Label **before** looking at the judge's verdict in `eval/judge.csv`. The next run of the evaluation computes your agreement with the judge (and Cohen's kappa).

## `reference.csv` and `shifted.csv`: generated

`uv run python data/generate.py` writes both: 40 normal requests from the synthetic client population (`reference.csv`) and 15 requests from a shifted segment, retirees aged 68-90 (`shifted.csv`). Then `uv run python main.py reference` turns `reference.csv` into `monitoring/reference_features.csv`. Commit all three.
