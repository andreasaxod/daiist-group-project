## Business case [TEAM]

*Who uses it, which decision or task it supports, what happens today without it (the baseline), the success metric, and a rough value in euros with the assumptions behind it.*

- User: the private-banking advisor preparing a recommendation (MiFID II suitability assessment).
- Today: the client fills in a questionnaire, a points grid gives a risk profile, and the advisor checks the portfolio and writes the suitability statement by hand.
- Baseline to beat: the points grid (`suitability.grid_class`) for the profile; manual writing time for the statement.
- Value: minutes saved per statement × statements per advisor per year × advisor cost per minute, plus the cost of an unsuitable recommendation avoided (complaints, regulatory findings). Say where each number comes from.

## Architecture [DRAFT]

```
request JSON (questionnaire + proposed portfolio)
   │
   ▼
Component A, risk model (scikit-learn, local)        train.py → models/risk_model.joblib
   risk class 1-5 + confidence (+ the points grid's class, for comparison)
   │
   ▼
Component B, suitability agent (Gemini, tool calling)
   tools: lookup_fund(fund_id) → KID data from data/funds.csv
          check_suitability(risk_class) → deterministic MiFID-style check (suitability.py)
   drafts the suitability statement; the verdict comes from the check, never from the LLM alone
   │
   ▼
review rule: confidence < 0.6, or not suitable, or LLM unavailable → the advisor reviews
```

One request: the advisor fills in the form, **Build request** produces the JSON, **Assess** sends it to `/run`. `pipeline.run()` validates it (anything that is not a questionnaire with a valid portfolio is refused as out of scope), component A predicts the risk class, and component B receives that class: the agent looks up every fund, calls the check with that class, and writes the statement from the result. The agent's statements are cached by (model, prompt version, request, class) in `cache/agent/`, so the evaluation, the drift demo and `check.py` do not spend the free Gemini quota twice.

Why these choices:
- scikit-learn for A: small tabular data, fits in Render's 512 MB, probabilities for a confidence-based review rule. Three models compared with 5-fold stratified cross-validation (sessions 2-3: model selection, cross-validation).
- An agent with tools for B (session 10: tools and orchestration), and a deterministic check as a tool, so that hallucinations (session 8) cannot change the regulatory verdict: the LLM explains, the rules decide.

## How to run it

1. `uv sync`, then `cp .env.example .env` and set `GEMINI_API_KEY`.
2. The model, the reference features and the agent cache are committed: `uv run python app.py` runs straight away.
3. To rebuild from scratch: `uv run python data/generate.py` (keeps existing labels), `uv run python train.py`, `uv run python main.py reference`, `uv run python main.py evaluate`.
4. Without `GEMINI_API_KEY`, the app still gives the risk class and the verdict, with a template statement, and sends every case to review.
